# H-2 · Calibrate credits per run on Copilot-hosted models

- **Human task:** H-2 · **Priority:** P1 · **Target:** 2026-12-04
- **Depends on:** PKT-8
- **Parent:** none

## Goal

Every credit figure in the kit is an estimate from assumed token shapes. They are `budget.creditsPerRun`, the cost page, and the ceiling's check. The one end-to-end run used the owner's own API key, so Copilot billed nothing. Only a person can run packets on Copilot-hosted models on a real seat and read the billing report, so this is workstream 4's human task. It replaces the estimates with measurements.

## Checklist

- [ ] **Prepare a sandbox.**
  - A sandbox repository with the phase's release installed by `-Profile solo`.
  - Every model in `models` Copilot-hosted, not BYOK.
  - MCP servers off in the packet sessions.
  - One seat whose user does nothing else in Copilot on a calibration day, since the report totals credits by user and date.
- [ ] **Optional, for numbers per role:** for the calibration days, put the dispatcher on a model of its own at the same rates, for example Claude Sonnet 5.5 against GPT-6.1 Sol for the other agents (`models.agents`). The report's split by model then separates the dispatcher.
- [ ] **Run one packet a day.** Start after 00:00 UTC and finish the same UTC day, since the report's days are UTC. Run at least 2 S, 2 M and 1 L packet. Note the harness and the models each agent ran on.
- [ ] **Read the report.** The next day, download the AI usage report from the billing settings. It gives credits by date, model and user, and input, output, cache-read and cache-write tokens per model. Record the day's figures.
- [ ] **Divide by the run counts.**
  - Count the runs: rounds, tiers, lenses and runs from `board rounds <pr> -Json`, the fix commits, and the resume sessions and CI-fix runs you saw.
  - Fit `dispatcher`, `dispatcherPerRound`, `dispatcherPerReviewerRun`, `implementer`, `implementerFix`, `reviewerByTier` and `laterRoundFactor`.
  - Check the 0.4-per-extra-lens factor for runs of three lenses.
  - Compare the result with `progress.ps1 -Credits` for the same packets.
- [ ] **Budget for it.** A packet is about 1,000 credits on the solo profile, so five packets are more than two months of one Business seat. Paid usage for the sandbox user is approved (about US$50): set its budget for additional usage to that before the first day.
- [ ] **Open a PR with the measured values.**
  - `budget.creditsPerRun` in `templates/packet-workflow.json` and the defaults in `skills/packet-board/scripts/PacketWorkflow.ps1` (the solo overlay inherits them).
  - docs/cost.md: its Calibrate section with the dates, and the per-run table.
  - The credit figures PKT-7 pinned in `tests/run-tests.ps1`, re-pinned to the measured rates, and cost.md's default per-packet table kept consistent with them (`tests/cases/cost-doc.tests.ps1`), so CI stays green.

  The changelog line (the new defaults change `progress.ps1 -Credits` and the ceiling's estimates for installs that rely on them) goes in the next release PR, as CONTRIBUTING.md says.
