# H-3 · Release the phase as 0.2.0

- **Human task:** H-3 · **Priority:** P1 · **Target:** 2026-11-19
- **Depends on:** PKT-8, PKT-9, H-4
- **Parent:** none

## Goal

CONTRIBUTING.md leaves `VERSION`, the changelog and the README's install tag to the owner's release PR, so the packets don't touch them. The phase adds features and changes nothing for an install that doesn't opt in, so it is a minor release.

## Checklist

- [ ] In a PR:
  - set `VERSION` to 0.2.0;
  - add the 0.2.0 entry at the top of `CHANGELOG.md`, from the packets' decision records;
  - change the install tag in the README to `v0.2.0`.
- [ ] The entry's "If you installed 0.1.1" section says:
  - nothing changes until the config sets `review.tierCap`, `budget.maxCreditsPerPacket` or `models.agents`;
  - rerun the installer to get the new skills and scripts, and commit them in a PR;
  - `-Profile solo` only chooses the template for a new config, so to move to the solo profile, copy its values in a PR;
  - `-PlanOnly` is refused on a full install;
  - every dispatch now runs `credit-check.ps1` at Select, before each round and before each fix run (it prints OFF when no ceiling is set), and a reviewer the host won't start now stops the round at Needs human;
  - the default `budget.creditsPerRun` now prices the dispatcher and tier 3 at GPT-6.1 Sol's rates, about half of 0.1.1's. A config keeps the rates written in it; copy the new ones in a PR to get the new estimates.
- [ ] Once it is merged and CI has passed on the merge commit, tag `v0.2.0` (annotated) and push the tag.
- [ ] Publish the GitHub release with the entry as its notes.
